## Overview

The `AgentCard` type defines the complete metadata and configuration for an Arkitec agent. It includes information about the agent's identity, capabilities, communication modes, skills, and supported interfaces.

## Type Definition

The `AgentCard` schema is defined using Zod validation in `src/main/services/agent/schemas/agent-card.ts`.

```typescript
interface AgentCard {
  name: string;
  description: string;
  version: string;
  email?: string;
  capabilities: {
    streaming?: boolean;
    pushNotifications?: boolean;
    extendedAgentCard?: boolean;
  };
  defaultInputModes: string[];
  defaultOutputModes: string[];
  skills: AgentSkill[];
  supportedInterfaces: Array<{
    url: string;
    protocolBinding: "JSONRPC" | "GRPC" | "HTTP+JSON";
    protocolVersion: string;
  }>;
}
```

## Validation Rules

The `AgentCard` schema enforces the following validation rules:

- **name**: Must be a non-empty string
- **description**: Must be a non-empty string
- **version**: Must be a non-empty string (semantic versioning recommended)
- **email**: Optional, but must be a valid email format if provided
- **capabilities**: All fields are optional booleans
- **defaultInputModes**: Must be an array of strings (can be empty)
- **defaultOutputModes**: Must be an array of strings (can be empty)
- **skills**: Must be an array of valid `AgentSkill` objects
- **supportedInterfaces**: Must be an array with valid URLs and protocol bindings

## Usage in Arkitec

The agent card is stored as `agent-card.json` in each agent's project directory. Arkitec uses this file to:

1. **Discover agents** in the workspace during project scanning
2. **Build the organization tree** showing agent hierarchies
3. **Enable agent communication** through supported interfaces
4. **Display agent information** in the UI and CLI
5. **Validate agent capabilities** before routing tasks
